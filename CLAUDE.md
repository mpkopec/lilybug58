# CLAUDE.md — lilybug58

Split keyboard that combines two existing designs. Bug54 provides the compact,
portable, column-staggered base with 27 keys per half; this repo is a fork of
ogruendel's Bug54. Two keys per half are added from Lily58, giving 29 keys per
half and 58 in total, which the name reflects: the Lily58-style index-finger
key, and a fifth key below the ring-finger column, where a Super key
typically sits.

## Toolchain

- PCB: KiCad. The two halves are separate projects, `kicad/lilybug58_left`
  and `kicad/lilybug58_right`.
- Firmware: QMK.

## Key naming and matrix

Key names are physical: they state where a key sits, not how it is wired,
and they are the same on both halves. The electrical matrix is defined
separately in the schematic, so a key's name and its matrix position need
not match.

- Columns C1–C6 run from the outer edge to the inner edge next to the
  microcontroller. In ergogen's names: C1 `far`, C2 `pinky`, C3 `ring`,
  C4 `middle`, C5 `index`, C6 `inner`.
- Rows R1–R4 run from the top (number) row to the bottom row.
- C7 is the thumb cluster, with three keys.
- `C6R3.5` is the added index-finger key. It sits beside C6 on the
  microcontroller side, centred vertically between C6R3 and C6R4, in the
  same position as the Lily58 extra key.
- `C3R5` is the added Super-key position, directly below C3R4. Only C3 has
  an R5.

Each half uses a 5-row × 7-column matrix, 12 GPIO, of which 29 positions are
populated. `C6R3.5` is the only key on matrix column 7; its matrix row, and
the assignment of every other key, are decided in the schematic.

## Microcontroller

The design proceeds in two phases. The first phase targets the Adafruit
Feather RP2040 only. The second phase replaces its footprint with stacked
footprints for several controller boards, so that builders can use the board
they already own; the set of boards is not yet decided.

## KiCad libraries

Symbols missing from KiCad's official libraries go into the project-local
library `kicad/lilybug58.kicad_sym`, registered in the project
`sym-lib-table` through `${KIPRJMOD}`, so that every clone resolves them
without extra installation.

The Feather RP2040 symbol is generated by KiPart from the pin table
`kicad/Adafruit_Feather_RP2040.csv` with `kipart -s row -m <csv> -o
kicad/lilybug58.kicad_sym`. Each alternate pin function is a separate row
with the same pin number, because every function needs its own electrical
type; for that reason KiPart's `-a` delimiter option is not used. The
naming and pin-type decisions are recorded in
`kicad/Adafruit_Feather_RP2040_review.md`. Re-running KiPart replaces the
whole symbol, including any layout made by hand in the Symbol Editor. The
footprint is the official generic Feather one.

Once the board is proven, the symbol is submitted as a merge request to
`kicad-symbols` on GitLab, from a separate fork. The project never points at
that fork. This keeps upstream review work, with its per-MR branches, out of
the project's own workflow.

## Firmware (QMK)

QMK supports the RP2040, but the Feather RP2040 is believed to have no
QMK board definition yet. The keyboard definition lives in `qmk/` in this
repo, laid out so that it can be copied unchanged into `keyboards/` of
`qmk_firmware`. A pull request to QMK follows later.

## Bug54 heritage and ergogen

The PCB files in `kicad/` were first generated by ergogen 4.2.1 from
`ergogen/config.yaml`, which extends Bug54's config with dedicated left and
right PCBs. From then on the KiCad PCBs are the master and are edited
directly in KiCad.

Ergogen remains as a placement sandbox for key positions and the board
outline. `npm run generate` writes only to the gitignored `ergogen/output/`,
so it never overwrites `kicad/`. Results are transferred to KiCad by hand:
switch coordinates are entered manually, and outlines can be imported into
Edge.Cuts from ergogen's DXF output. Ergogen exports an outline as DXF only
when its name has no leading underscore, so `_board` and `_board_right` are
currently not exported. Ergogen has no schematic; its nets come from
footprint parameters, so its PCBs cannot stay in sync with the KiCad
schematic and are never copied over the KiCad files. Ergogen is removed once
the layout is frozen.

The Bug54 ZMK setup, README, BOM and photos are removed from the tree and
remain in git history (`git log -- boards/` and so on). `mech/Case.FCStd` is
Bug54's FreeCAD case, kept as the starting point for the lilybug58 case.
